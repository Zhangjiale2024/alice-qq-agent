# Alice QQ Agent

一个跑在 QQ 上的 LLM Agent。它会自己决定调哪个工具、自己查资料、自己记住你是谁，
做不到的时候会说做不到。

715 项离线测试，核心逻辑 14400 多行不依赖任何第三方包。

## 它到底会做哪些事

一开始这只是个"能聊天的 QQ 机器人"。做着做着事情变成了另外的样子：
聊到需要最新消息时得真去查，用户说"记住这个"时得真写进库，
群里有人发广告时得判断该不该管。这些都要求它**先决定做什么，再去执行，
然后拿执行结果回来说话**——而不是凭印象编一个回答。

我把这些反复用到的能力做成了工具，交给模型自己挑：

| 工具 | 它解决的场景 |
|---|---|
| `remember` | 用户明确说"记住"的时候，写进他自己的记忆库 |
| `web_search` | 问最新活动、价格、规则这类会变的信息 |
| `academic_search` | 查论文。走 CrossRef / Semantic Scholar / arXiv |

这是它跑起来的样子（`--trace` 会把决策链打出来）：

```text
爱丽丝 > 已记录完成！爱丽丝把这条信息存进记忆库了。
        「不吃香菜」——爱丽丝记下了，以后点菜的时候会帮你避开的！

── 决策链 ──
  决策      replied（已回复）
  模型      openai / deepseek-chat
  工具目录  remember✓  web_search✓  academic_search✓
  ① 模型决定调用  remember
  ② 执行结果      成功：已记录。
  ③ 二次生成      把工具结果作为 role=tool 回灌，再问一次模型
  记忆落库  2 条
```

模型自己决定调 `remember`，引擎执行完把结果塞回对话（`role=tool`），
模型再根据真实结果组织回复。所以"我记住了"这句话背后是真有一次写库的。

## 两条检索路径

这里有个我想记下来的设计取舍。

最自然的做法是让模型自己判断该不该搜。但实际跑下来，
**角色扮演模式下模型经常不调工具**——它更愿意顺着人设聊下去。
而用户问"今天有什么活动"的时候，我们必须真的查过。

所以除了让模型可以主动调工具，引擎自己也会判断：这句话是不是在问
时效性的事，是的话先查了再交给模型。两条路都保留，`--trace` 里能看出走的是哪条：

```text
  检索路径      引擎判定为先检索（模型未主动调工具）
                结果作为上下文注入提示词，不走 role=tool 回灌
  检索      provider=bilibili ok=True 条数=6 耗时=5.1
```

## 护栏：它最容易犯的错不是答错

语言模型最麻烦的失败不是胡说八道，而是**声称做了一件其实没做的事**。
因为它看起来成功了，用户不会怀疑。

所以我用确定的代码拦住三类，而不是在提示词里请求它自觉：

- **能力幻觉**。回复里出现"语音已经发给你了"但实际没有媒体附件时，
  把那句话删掉，并如实说明。同类的还有"已保存""已撤回"。
- **敏感信息拒存**。用户说"记住我的身份证号"时，服务端的
  `looks_sensitive()` 会拦下这次写入，换任何模型都拦得住。
- **管理动作如实回填**。撤回或禁言失败时，把真实原因告诉管理员，
  不假装成功。

## 测试

```bash
python -m unittest discover -s tests -t .     # 715 项，不需要网络
python -m aliceqq --test-plan                 # 环境自检 + 自测 + 手工测试清单
python -m aliceqq --simulate                  # 用真实模型跑 12 个场景
```

这些测试分三层，能证明的东西不一样：

| 层 | 需要什么 | 能证明 | 不能证明 |
|---|---|---|---|
| 离线单元测试 | 无 | 逻辑对不对（模式隔离、限流、护栏、工具分发） | 说话像不像、消息真发出去没有 |
| 真实服务 | 网络和 API Key | 模型真的会调工具、检索真的返回 | QQ 那边真的收到了 |
| 真实 QQ | NoneBot + NapCat | 端到端送达、权限、管理动作生效 | |

我特意把"不能证明什么"也列出来。测试全绿最容易造成的错觉，
就是以为没问题了。事实上上面三层里，第三层我到现在也没有充分验证过。

CI 跑在 Ubuntu 和 Windows 上，两个 Python 版本，而且**故意不装任何依赖**——
这样"核心零第三方依赖"就不只是 README 里的一句话，
而是每次提交都会被验证的事实。

## 怎么跑起来

```bash
python -m aliceqq --setup     # 检查环境、装依赖、生成配置、跑测试
```

不需要 QQ，也不需要 API Key，跑完就能试：

```bash
python -m aliceqq --demo
python -m aliceqq --repl
python -m aliceqq --show-prompt "你好"     # 看实际发给模型的完整上下文
```

想接真实模型，在 `.env` 里填 `LLM_API_KEY`，然后：

```bash
python -m aliceqq "帮我记住我喜欢明日方舟" --live --trace
```

接 QQ 的话：

```bash
python -m aliceqq --serve     # 需要 NoneBot2 和 NapCat
```

## 代码结构

```
aliceqq/                    业务逻辑。这个目录不 import 任何第三方库
  engine.py                 主流程：组装上下文 -> 问模型 -> 执行工具 -> 过护栏
  tools.py                  工具注册表，顺便生成 OpenAI 格式的 tool schema
  llm.py                    OpenAI 兼容客户端，用 urllib 手写的，没引 SDK
  memory.py search.py academic.py moderation.py media.py singing.py
  adapters/
    nonebot_plugin_alice.py 唯一的适配层，只做事件翻译

integrations/nonebot/run.py 启动壳
```

核心包不碰第三方库有三个实际好处，不是为了好看：

一是能测。715 项测试全部离线、确定、跑一遍一分钟出头，不用 mock 网络。
二是能换壳。适配层只有几十行，想接别的协议只改那一层。
三是能跑。`python -m aliceqq "你好"` 在任何一台装了 Python 的机器上都能演示。

真的需要第三方的地方都做成了延迟导入，比如语音识别用的 `faster-whisper`。
没装的时候它如实说"不可用"，其它功能一点不受影响。

## 踩过的坑

放在这里是因为**这些比功能列表更能说明问题**。每一条都是真的踩了，
包括我一开始判断错的地方。详细的排查过程我写在
[docs/踩坑记录.md](docs/踩坑记录.md) 里，这里只列结论。

| 现象 | 真正的原因 | 我当时以为 |
|---|---|---|
| 工具调用从来不触发 | 工具定义写好了、执行器也写好了，但调用模型时漏传了 `tools` 参数，模型根本不知道有工具可用 | 以为提示词里写了工具目录就够了 |
| 语音发不出去 | 文本里夹了英文，服务端缺 nltk 资源返回 HTTP 400，然后静默退回了备用音色 | 以为是意图识别漏判（其实两个问题都有） |
| 长音频转换崩 `0xC0000005` | Windows 页面文件被别的程序占满，不是代码问题 | 当成"间歇性故障"，因为有时能成功 |
| 指标显示高频降了 6% | 拿 44.1kHz 的源和 40kHz 的成品直接比，是跨采样率比较得出的假象 | 信了那个数字 |
| 搜《群青》出来《群青信号》 | 只判断标题里"包含"歌名，而后者是另一首歌，还因为更短排到了前面 | 以为过滤已经够严 |
| 30 秒的请求产出 195 秒成品 | 中间产物同名覆盖，UVR5 见到同名文件就跳过重算 | 先怀疑了编码和内存 |
| 测试号称零依赖其实不是 | `test_ffmpeg` 顶层 `import numpy`，干净环境里整个文件收集失败 | 一直在装好了依赖的环境里跑 |

有三条我现在还记得很清楚：

**"没有报错"不等于"没有失败"。** 进程静默退出的时候要看退出码。
`-1073741819` 是 Windows 的 `0xC0000005`，一看就知道是原生层崩了，
而不是 Python 逻辑问题。我在这上面绕了很久。

**接线漏洞最难发现。** 工具的注册表、schema、执行器、回灌循环全都在，
每个部分单独看都正确。唯一的缺陷是调用时漏传了一个参数。
结果整套能力静默失效，没有任何报错，测试也全绿。
这种 bug 比语法错误难查得多。

**本机什么都装了，会掩盖问题。** 上面七条里有三条是换个空目录
clone 一次才暴露的。所以现在每次交付前我都会在干净目录跑一遍 `--setup`，
这一步比继续改代码更值。

## 维护脚本

```bash
python scripts/项目自检.py     # 上传或交付前跑一次
```

它会检查测试覆盖不到的那些事：文档里的数字和实现是否一致、
有没有混进不该提交的文件、`.env` 有没有重复键、
代码里有没有静默吞异常的写法、有没有残留的个人信息。
每一项都给出具体怎么改。

| 脚本 | 管什么 |
|---|---|
| `项目自检.py` | 入口，把下面几个串起来 |
| `隐私扫描.py` | 从真实 `.env` 取值反查残留 |
| `env审计.py` | 查 `.env` 的重复键、空值、BOM |
| `代码巡检.py` | 找静默吞异常、裸 `except`、过长的函数 |
| `硬编码路径检查.py` | 查换台机器就跑不起来的路径 |
| `链路体检.py` | 查 QQ ↔ NapCat ↔ NoneBot 这条链通不通 |
| `安装钩子.py` | 装 pre-commit，让密钥进不了版本库 |
| `重置配置.py` | 备份并重建 `.env` |
| `推送GitHub.py` | 推送前检查，会先排查代理状态 |

密钥这件事我做了三层：`.gitignore` 挡住文件，隐私扫描反查残留，
pre-commit 钩子在提交时直接拒绝。因为密钥一旦提交过，
删掉文件也没用，它会留在 git 历史里。

## 常见问题

**在 cmd 里 `rm .env` 报错说不是内部或外部命令**

`rm` 是 Linux 和 macOS 的写法。三种 shell 都不一样，
所以直接用项目自带的脚本更省事：

```bash
python scripts\重置配置.py
```

**配置改了不生效**

先查有没有重复键，后面的会静默覆盖前面的：

```bash
python scripts\env审计.py .env
```

**`--serve` 说缺 NoneBot2**

这个只在接真实 QQ 时用得上，`--setup` 会自动装。
不装也能用：`python -m aliceqq --repl` 直接本地聊天。

**机器人不回消息**

先跑链路体检：

```bash
python scripts\链路体检.py
```

它会帮你分清两种看起来一样、但处理方法相反的情况：
反向 WebSocket 断了（等 NapCat 重连就行），
还是 QQ 登录被静默踢下线了（只能重新登录）。

## 现在还缺什么

写在前面而不是藏在最后：

1. 适配层的消息收发没有在真机上充分验证过。插件能正常加载，
   但媒体构造和群管理动作没有自动化测试，因为它们需要真实 QQ 对面有人。
   这是目前最大的空白。
2. 没有多轮工具编排。工具结果回灌之后只会再问一次模型，
   不做完整的 ReAct 循环。
3. 反广告是规则式的，不是模型判断。好处是可解释、误伤少，
   代价是绕开词表的广告抓不到。
4. 唱歌那条链路没有自动化测试，只有意图识别和缓存有覆盖。
5. 单进程部署，用的是 SQLite。多实例要换共享存储。
