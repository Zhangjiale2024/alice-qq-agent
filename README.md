# 爱丽丝 QQ Agent

一个接入 QQ 的角色陪伴 Agent。**核心逻辑 11,756 行纯标准库实现**，
**706 项离线测试全绿**，不需要任何第三方包就能跑通与测试。

> 这个仓库想展示的不是"我做了个聊天机器人"，而是**怎么把一个会跟真实用户、
> 真实网络、真实故障打交道的系统做可靠**：分层、护栏、可观测性，
> 以及一份**诚实的失败记录**。

## 架构：为什么这样分层

```
IncomingMessage ──> Engine（全部业务逻辑，纯标准库）──> Outcome
                                                            │
                          ┌─────────────────────────────────┘
                          ▼
                adapters/nonebot_plugin_alice.py
                （只做：事件翻译 + 把 Outcome 变成 OneBot 调用）
```

**核心约束：`aliceqq` 包不 import 任何第三方库。**

这不是洁癖，是三条实际收益：

1. **能测**。706 项测试全部离线、确定性、毫秒级，不需要 mock 网络栈。
2. **能换壳**。适配层只有几十行；换成别的协议只改那一层。
3. **能跑**。`python -m aliceqq "你好"` 在没装任何依赖的机器上就能演示。

第三方依赖只出现在**可选**位置，且都是延迟导入：

```python
# aliceqq/asr.py —— 没装 faster-whisper 就如实报"不可用"，不影响其它功能
try:
    import faster_whisper
except Exception as exc:
    self._load_error = f"未安装 faster-whisper（{type(exc).__name__}）"
```

关键设计取舍：

| 设计 | 为什么 |
|---|---|
| 媒体只挂在**最后一条**消息上 | 否则分条回复会连发好几张图 |
| `Outcome` 里带 `debug` 字典 | 管理动作、决策理由都挂在里面，适配层据此翻译；核心不需要知道 OneBot |
| 记忆按 `user_id` 物理隔离 | 隐私硬线，有专门测试卡这条 |
| 模式**按会话**存储 | 群里切 `/助手` 不该影响私聊；有 3 条测试覆盖三种作用域规则 |

## 四类工程问题与解法

### 1. 网络不可靠

真实环境里代理会挂、镜像会 412、cookie 会被吞。这里做了：

- **代理自动降级**：系统代理连不通就直连重试，不靠用户改配置
- **多源检索回退**：一个搜索源失败就换下一个，并在回复里说明来源
- **SSRF 拦截**：只允许 http/https，拒绝内网地址
- **B 站登录态**：签到接口返回 `code=-101` 时**仍然携带** `data.wbi_img`——
  不能因为 code 非 0 就丢弃响应（这是实测踩出来的）

### 2. 模型会撒谎

LLM 会声称"已经撤回/已经发送/已经保存"，而实际什么都没做。
这类幻觉对用户是最有害的，因为它**看起来成功了**。

确定性护栏（不依赖提示词自觉）：

```python
_strip_media_overclaim()      # 没有媒体却声称"语音已发给你了" -> 剥掉那句话并如实说明
honesty.py                    # 能力幻觉 / 思考泄漏 / 假保存 / 编造文献
```

群管理动作**必须回填真实结果**：撤回/禁言/踢出失败时，把真实原因说给管理员听。

### 3. 真实用户会做意外的事

真实用词和测试用例不一样。上线后用户实际说过：

```
"唱一首蔚蓝档案的《准备出发》"     -> 出处前缀也被当歌名
"让你唱全速向光不是反乌托邦"        -> 纠正句被当歌名
```

这些**单测全绿也没抓到**，因为测试数据太规范。修完之后，
新的回归用例**直接抄用户原话**。

### 4. 系统会耗尽资源

Windows 上跑本地模型遇到 `0xC0000005` 访问违规崩溃。
排查后发现**根因不是代码**：

```
可用虚拟内存只剩 1.7 GB（提交上限 53.3 GB 已被其它程序占满）
页面文件在 C 盘，而 C 盘只剩 11 GB，系统想扩也扩不了
```

对策不是"优化代码"，而是**把资源消耗做成可降级**：
长音频分段处理、失败重试、输出时长校验、任务可取消。

## 测试：三层金字塔

```bash
python -m aliceqq --test-plan          # 第 0 层：一条命令看全景
python -m unittest discover -s tests -t .   # 第 1 层：706 项离线测试
python -m aliceqq --simulate           # 第 2 层：真实模型跑 12 个场景
```

| 层 | 依赖 | 能证明什么 | **证明不了什么** |
|---|---|---|---|
| 1 离线单元测试 | 无 | 逻辑正确性（模式/隔离/限流/护栏/审核判定） | 文风、真实送达、音色好坏 |
| 2 真实服务 | 网络 + API Key | 模型真的会用提示词、检索真的返回 | QQ 侧真的发出去了 |
| 3 真实 QQ | NoneBot + NapCat | 端到端送达、权限、管理动作真的生效 | —— |

**为什么强调"证明不了什么"**：测试全绿最容易造成的错觉，
就是以为没有问题了。三层里任何一层都不能代替下一层。

`--test-plan` 还会给出 **46 条人工测试清单**（该发什么 + 期待什么），
并且**失败时列出具体是哪几条**，而不是只说"存在失败"。

## 踩过的坑（真实记录）

这部分是刻意保留的。**每个 bug 都记了真实根因**，包括我自己判断错的地方。

| 现象 | 真实根因 | 我最初的误判 |
|---|---|---|
| 语音发不出去 | 文本夹英文 → 服务端缺 nltk 资源返回 HTTP 400 → 静默回退备用音色 | 以为是意图识别漏判（其实两个问题都有） |
| 长音频转换崩 `0xC0000005` | **Windows 页面文件耗尽**，不是代码 bug | 误判成"间歇性故障"，因为有时成功 |
| 指标说高频降了 6% | **跨采样率比较**（源 44.1k vs 成品 40k）得出的假象 | 信了这个数字 |
| 搜《群青》出来《群青信号》 | 只判"包含"，而后者是**另一首歌**且更短所以排前面 | 以为过滤已经够严 |
| 30 秒请求产出 195 秒成品 | 中间产物**同名覆盖**，且 UVR5 见同名就跳过重算 | 先怀疑了编码和内存 |
| 示例 QQ 号被反复重试 | 测试时的 `--user 10001` 进了档案库 | —— |

最后一条的教训值得单独说：

> **"没有报错"不等于"没有失败"。**
> 进程静默退出时，要看**退出码**：`-1073741819` 就是 Windows 的 `0xC0000005`，
> 一看就知道是原生层崩了，而不是 Python 逻辑问题。

## 快速开始

### 离线（0 依赖，不需要 QQ 和 API Key）

```bash
git clone <this-repo> && cd alice-qq-agent

python -m aliceqq --demo                      # 完整自检演示
python -m aliceqq "你好，爱丽丝" --user 123456
python -m aliceqq --repl                      # 交互式
python -m aliceqq --show-prompt               # 看实际注入的完整提示词（排障用）
```

### 接真实模型

```bash
cp .env.example .env      # 填入 LLM_API_KEY
python -m aliceqq --probe                     # 自动探测哪家服务商认得这把 key
python -m aliceqq "你好" --live               # 不加 --live 强制走离线 mock
```

### 接 QQ

```bash
pip install nonebot2 nonebot-adapter-onebot
cd integrations/nonebot && python run.py
# NapCat 反向 WS 指向 ws://127.0.0.1:8095/onebot/v11/ws
```

链路不通时先跑体检（只读，不改配置）：

```bash
python scripts/链路体检.py
```

它会分清两种表象相同、对策相反的情况：
**反向 WS 断了**（等 NapCat 重连）vs **QQ 登录被静默踢下线**（只能重新登录）。

## 配置

配置优先级：**环境变量 > `.env` > `config.json` > 默认值**。

所有凭据在对外输出时**一律脱敏为 `***`**——这条是实测发现的缺陷：
早期只脱敏了 LLM 的 key，后来新增的检索 key 会原样出现在 `public_dict()` 里。
现已统一处理并有测试覆盖。

功能开关都在 `.env`，默认策略刻意保守：

| 开关 | 默认 | 理由 |
|---|---|---|
| `GROUP_CHAT_ENABLED` | 开 | 但访问默认是 `approved_groups`，**新群不会响应** |
| `VOICE_ENABLED` | **关** | 需要本地 TTS 服务 |
| `SINGING_ENABLED` | **关** | 一次跑 60~90 秒吃满 CPU；且涉及翻唱版权 |
| 审核（反广告） | **试运行** | `dry_run=True` 只观察不处罚；高风险动作一律要管理员确认 |

## 诚实的边界

写在前面，而不是藏在最后：

1. **适配层的消息收发未经实机验证**。插件**加载**已实跑确认
   （`nonebot 2.5.0` + `load_plugin` 成功），但媒体构造
   （`[CQ:record]` / `[CQ:image]`）与群管理动作没有自动化测试。
2. **唱歌链路无自动化测试**。只有意图识别/缓存/取消有覆盖（21 项）；
   真正的音频流水线靠手工验证。
3. **反广告是规则式的**，不是模型判定。好处是可解释、误伤少；
   代价是绕开词表的广告抓不到。
4. **警告不会自动过期**，累计次数永久保留。
5. **批量撤回未实现**（只有单条）。
6. **检索结果真实性**只能靠"带来源 + 标注时效"约束，无法自动验证。
7. **单进程部署**。SQLite 适合单机；多实例需要换共享存储。

## 维护脚本

上传或交付前跑一次自检：

```bash
python scripts/项目自检.py
```

它检查测试管不到的事：文档与实现是否一致、有没有混入不该提交的文件、
`.env` 结构问题、静默吞异常的写法、敏感信息残留，**每条都给出可执行的修法**。

| 脚本 | 作用 |
|---|---|
| `项目自检.py` | 入口，串起下面几个 |
| `隐私扫描.py` | 从真实 `.env` 取值反查残留（不靠"像不像密钥"猜） |
| `env审计.py` | 查 `.env` 重复键/空值/BOM（**不打印任何值**） |
| `代码巡检.py` | 找静默吞异常、裸 `except`、函数过长 |
| `链路体检.py` | 查 QQ↔NapCat↔NoneBot 链路通不通（只读） |
| `安装钩子.py` | 装 pre-commit，**让密钥根本进不了版本库** |

保密上做了三层：`.gitignore` → 隐私扫描 → **pre-commit 钩子自动拦截**。
密钥一旦提交，删文件也没用（会留在 git 历史里），所以必须从源头挡住。
