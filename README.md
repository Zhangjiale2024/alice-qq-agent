## 30 秒看它怎么"想"

不是"把提示词拼好丢给模型"——它有真实的**决策链**。这是实跑输出
（`python -m aliceqq "帮我记住我不吃香菜" --live --trace`）：

```text
爱丽丝 > 已记录完成！爱丽丝把这条信息存进记忆库了。
        「不吃香菜」——爱丽丝记下了，以后点菜的时候会帮你避开的！

── 决策链 ──
  决策      replied（已回复）
  模型      openai / deepseek-chat
  工具目录  remember✓  web_search✓  academic_search✓
  ① 模型决定调用  remember
  ② 执行结果      成功：已记录。
  ③ 二次生成      把工具结果作为 role=tool 回灌，再问一次模型
  记忆落库  2 条
```

模型**自己决定**要调 `remember`，引擎执行后把结果作为 `role=tool` 回灌，
模型再基于真实执行结果生成回复。**不是模型声称"我记住了"就完事。**

```
                     ┌─────────────────────────────────────────┐
  QQ 消息 ───────────▶  上下文组装（Context Assembly）          │
                     │  记忆 · 群配置 · 知识库 · 权限 · 额度      │
                     │  · 可用工具目录 · 媒体能力（都反映真实状态）│
                     └────────────────────┬────────────────────┘
                                          │
                     ┌────────────────────▼────────────────────┐
                     │  决策：把 tools schema 传给模型          │
                     │  tool_choice = "auto"                   │
                     └────────────────────┬────────────────────┘
                                          │
        ┌─────────────────────────────────┼─────────────────────────────────┐
        │                                 │                                 │
  ┌─────▼──────┐               ┌──────────▼──────────┐            ┌─────────▼────────┐
  │ ① 模型调工具│               │ ② 引擎判定先检索     │            │ ③ 纯对话         │
  │  remember   │               │  时效性问题直接查    │            │  不调工具        │
  │  web_search │               │  （不依赖模型自觉）  │            │                  │
  │  academic_  │               └──────────┬──────────┘            └─────────┬────────┘
  │  search     │                          │                                 │
  └─────┬───────┘                          │ 结果注入提示词                   │
        │ role=tool 回灌                   │                                 │
        └──────────────────┬───────────────┴─────────────────────────────────┘
                           │
              ┌────────────▼────────────┐
              │  确定性护栏（不靠模型自觉）│
              │  · 能力幻觉拦截           │
              │  · 敏感信息拒存           │
              │  · 管理动作结果如实回填    │
              └────────────┬────────────┘
                           │
                    回复 / 媒体 / 管理动作
```

### 为什么有两条检索路径

`_maybe_search` 的代码注释写了原因：

> 这条路径不依赖模型主动调用工具——**很多模型在角色扮演模式下并不会去调工具**，
> 而用户问"今天有什么活动"时我们必须真的查过。

所以引擎在**时效性问题**上会自己先查、把结果注入上下文；同时保留模型
主动调工具的能力。两条路径都能在 `--trace` 里看到区别。

### 工具

| 工具 | 作用 | 关键约束 |
|---|---|---|
| `remember` | 把用户**明确要求**长期保存的信息写进他自己的记忆库 | 敏感信息**按规则拒存**；只能写当前用户 |
| `web_search` | 联网检索 | 多源回退；引用必须带来源 |
| `academic_search` | CrossRef / Semantic Scholar / arXiv 文献检索 | 只给它学术问题；**不许编造卷号页码** |

**不可用的工具不会写进 schema。** 这是刻意的：把不可用的工具递给模型
等于给它递刀子——它会尝试调用、拿到失败结果，或者在回复里演一遍
"我去查一下"。提示词里仍会列出不可用的工具并标注"不能尝试调用"，
两条信息保持一致，模型不会困惑。

## 三条护栏：做不到的事，不许说做到了

LLM 最有害的失败模式不是答错，而是**声称做了一件其实没做的事**——
因为它看起来成功了。这里用**确定性代码**（不是提示词请求）拦住三类：

### 1. 能力幻觉

```python
_strip_media_overclaim()   # 没有媒体却声称"语音已发给你了" -> 剥掉并如实说明
honesty.py                 # 思考泄漏 / 假保存 / 编造文献
```

### 2. 敏感信息拒存

```text
用户 > 记住我的身份证号是 123456789012345678
爱丽丝 > 爱丽丝可以记住的是别的：比如你希望爱丽丝怎么称呼你、
        你喜欢什么游戏…… 这些才是适合放进「存档」的东西！
```

**不是模型自己把住的，是服务端 `looks_sensitive()` 拦下的**——
换任何模型都拦得住。

### 3. 管理动作结果如实回填

撤回/禁言/踢出失败时，把**真实原因**说给管理员听，绝不假装成功。

## 观察 Agent：`--trace`

Agent 类项目有一半价值在"它怎么决定的"。`--trace` 把决策链打出来。
以下都是**实跑输出**：

**① 模型主动调工具**

```text
── 决策链 ──
  决策      replied（已回复）
  模型      openai / deepseek-chat
  工具目录  remember✓  web_search✓  academic_search✓
  ① 模型决定调用  remember
  ② 执行结果      成功：已记录。
  ③ 二次生成      把工具结果作为 role=tool 回灌，再问一次模型
  记忆落库  2 条
```

**② 引擎判定先检索（模型未调工具）**

```text
  检索路径      引擎判定为先检索（模型未主动调工具）
                结果作为上下文注入提示词，不走 role=tool 回灌
  检索      provider=bilibili ok=True 条数=6 耗时=5.1
```

**③ 护栏拦截**

```text
  护栏拦截  memory_rejected: 1 条（敏感信息按规则不保存）
```

`--trace` **只打印真实发生过的事**：没有工具调用就不打那一段，
不存在的阶段绝不编造。

## 架构：为什么核心包不 import 第三方库

```
aliceqq/                            业务逻辑（纯标准库）
  engine.py                         决策引擎：上下文 → 模型 → 工具 → 护栏
  tools.py                          工具注册表 + OpenAI tool schema
  llm.py                            OpenAI 兼容客户端（urllib 手写，不引 SDK）
  memory.py  search.py  academic.py  moderation.py  media.py  singing.py
  adapters/nonebot_plugin_alice.py  ← 唯一的适配层，只做事件翻译

integrations/nonebot/run.py         启动壳
```

三条实际收益：

1. **能测**——715 项测试全离线、确定性、不需要 mock 网络栈
2. **能换壳**——适配层只有几十行；换协议只改那一层
3. **能跑**——`python -m aliceqq "你好"` 在没装任何依赖的机器上就能演示

第三方依赖只出现在**可选**位置，且都是延迟导入。没装 `faster-whisper`
时它如实报"不可用"，不影响其它任何功能。

## 踩过的坑（真实记录）

这部分刻意保留。**每个 bug 都记了真实根因**，包括我判断错的地方。

| 现象 | 真实根因 | 我最初的误判 |
|---|---|---|
| **工具调用从来不触发** | 工具 schema **从没传给模型**——`llm.chat()` 支持 `tools=` 也会解析 `tool_calls`，但引擎从未传参，`reply.tool_calls` 恒为空 | 以为提示词里写了工具目录就够了 |
| 语音发不出去 | 文本夹英文 → 服务端缺 nltk 资源返回 HTTP 400 → **静默回退**备用音色 | 以为是意图识别漏判（其实两个都有） |
| 长音频转换崩 `0xC0000005` | **Windows 页面文件耗尽**，不是代码 bug | 误判成"间歇性故障"，因为有时成功 |
| 指标说高频降了 6% | **跨采样率比较**（源 44.1k vs 成品 40k）得出的假象 | 信了那个数字 |
| 搜《群青》出来《群青信号》 | 只判"包含"，而后者是**另一首歌**且更短所以排前面 | 以为过滤已经够严 |
| 30 秒请求产出 195 秒成品 | 中间产物**同名覆盖**，UVR5 见同名就跳过重算 | 先怀疑了编码和内存 |
| 测试"零依赖"其实不是 | `test_ffmpeg` 顶层 `import numpy` → 干净环境里**整个文件收集失败** | 一直在装了依赖的环境跑，看不到 |

两条最值得记的教训：

> **"没有报错"不等于"没有失败"。** 进程静默退出时要看**退出码**：
> `-1073741819` 就是 Windows 的 `0xC0000005`，一看就知道是原生层崩了，
> 而不是 Python 逻辑问题。

> **接线漏洞最难发现。** 工具注册表、schema、执行器、回灌循环**全都在**，
> 每一部分单独看都正确，只是调用时漏传了一个参数——
> 于是整套能力静默失效，而且**没有任何报错**。

## 诚实的边界

写在前面，不藏在最后：

1. **适配层的消息收发未经实机验证**。插件**加载**已实跑确认，
   但媒体构造与群管理动作没有自动化测试。
2. **无多轮工具编排**。工具结果回灌后只再问一次模型，
   不做"模型连续调多个工具"的完整 ReAct 循环。
3. **反广告是规则式的**，不是模型判定。可解释、误伤少，但绕开词表的抓不到。
4. **单进程部署**。SQLite 适合单机；多实例需换共享存储。
5. **唱歌链路无自动化测试**，只有意图识别/缓存/取消有覆盖。
6. **检索结果真实性**只能靠"带来源 + 标注时效"约束，无法自动验证。
