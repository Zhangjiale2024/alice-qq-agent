**"中文用中文CV"的方向是对的**：机器人说中文，参考音频以中配（皛四白）为主，
用日配（田中美海）当参考去直接克隆，说中文会带日式口音。

注意：这两个名字对应**两位不同的自然人**，各自都有自己的声音权益。
按你们的方案要混合两者——那**是两个权利人，不是一个**，需要分别取得许可。

### 更正：B 站上那些"蔚蓝档案中配"视频是什么

我先前写过"大量是同人/二创配音"——**那句话不准确，是我凭几个标题下的结论，没有验证。**
用 B 站检索抽样 40 条后，实际情况是三类混合，且**最主要的一类不是二创**：

| 类别 | 实例（均来自实际抽样） | 说明 |
| --- | --- | --- |
| **官方中配的录屏/语音集**（最多） | 《蔚蓝档案国服中文配音语音集--未花（泳装）》，简介写明"CV：龟娘 **版权归属于蔚蓝档案**"；《国服全配音主线剧情》；《天童爱丽丝的60大中文全配音》 | 从游戏里录下来的**官方语音**，UP 主只是整理搬运 |
| **官方自己的宣传物料** | 《蔚蓝档案》中文配音档案 VOL.1——阿拜多斯篇，**UP 主就是官方号「蔚蓝档案」**，简介直接列 CV 名单 | 官方发布，可信度最高 |
| **真正的 AI / 同人配音**（少数） | 《1：1复制原版配音！爱丽丝手把手教你蔚蓝档案AI配音》；《【碧蓝档案】全学生AI音色模型发布（内含数据集及标注）》 | 这类才是二创，且有不少是 AI 合成 |

**所以"蔚蓝档案中配"这个标签本身不能用来判断来源。** 判别方法：

- 看**简介**：写了"CV：某某""版权归属于蔚蓝档案"的，是官方语音搬运；
- 看 **UP 主**：账号名就叫「蔚蓝档案」的是官方号；
- 看**内容性质**：主线剧情完整录播基本是官方中配；
  单角色"XX大语音集"要留意是否标注了 CV 姓名。

**对训练参考音频的实际影响**：
那批"官方语音集"确实是最方便的中文参考来源，但"版权归属于蔚蓝档案"这句话是 UP 主自己标的——
**它说明版权在游戏方，不在 UP 主**。所以拿它当训练素材，需要谈的是**发行方**，
而不是那个搬运的 UP 主。这一点比"找 UP 主要授权"更麻烦，不是更简单。

**顺带一个旁证**：抽样中出现了《［南宁BAO］现场实录爱丽丝CV皛四白老师配音》，
与前面确认的中配身份一致。

**另一个巧合**：抽样里还混进了《同样的GPT-SoVITS，为什么你的毫无感情？3个技巧帮你完美破局！》
这类教程——说明"AI 语音没感情"是这个圈子公认的痛点，
也印证了本方案把"情感"单列一层是必要的。

## 二、法律边界（这是决定性的）

### 权威依据

《民法典》第一千零二十三条第二款：

    对自然人声音的保护，参照适用肖像权保护的有关规定。

最高人民法院《人民法院报》「法答网精选答问（第十九批）——人格权专题」
（2025-05-08，咨询人：杭州互联网法院；答疑专家：杭州中院）答疑要点：

1. 声音与肖像一样**具有人格属性**，参照适用民法典第 1018、1019、1020、1021、1022 条。
2. 保护客体是"**自然人的声音本身，即纯粹的声音**"，既非声音载体，也非声音内容。
3. **关键判例**：在"**殷某桢诉北京某智能科技公司等人格权纠纷案**"
   （入库编号：**2025-07-2-474-001**）中，裁判要旨认为——
   **未经自然人许可使用经人工智能技术处理的声音，构成对自然人声音权益的侵权。**
   这一条几乎就是为"音色克隆"写的。
4. 受保护的声音需"**足以识别到特定的自然人**，具有明显的特征指向性"。
5. **例外**：单纯模仿他人声音（如电视台"模仿秀"）**不宜认定**为侵权。
   注意这是对"人工模仿"的表述，**对技术克隆不利**。
6. 合理使用情形（民法典第 1020 条）：教学科研、新闻报道、依法履职等。
   **"运营一个公开的角色陪伴机器人"不在其中。**

### 落到你的场景

| 用法 | 风险 |
| --- | --- |
| 本地自己玩、不公开 | 侵权认定可能性相对低（未公开使用），但**未经许可制作**仍有争议 |
| 公开给陌生用户 / 多个 QQ 群使用 | **风险高**。属于"未经许可使用、公开他人声音"，且有商业化色彩 |
| 混合日配 + 中配两个音色 | **不当然免责**。混合后若仍能识别出任一自然人，仍可能侵权，而且是**两个**权利人的问题 |

## 三、技术方案（三个层次）

### 方案 A：零样本克隆（最快，5 秒参考音频）

**GPT-SoVITS**（中文社区最成熟）：

    TTS_PROVIDER=gptsovits
    TTS_CLONE_URL=http://127.0.0.1:9880
    TTS_CLONE_REF_AUDIO=/voices/alice_zh.wav
    TTS_CLONE_REF_AUDIO_2=/voices/alice_ja.wav
    TTS_CLONE_PROMPT_TEXT=参考音频里说的那句话
    TTS_LANGUAGE=zh

GPT-SoVITS 的 ref_audio_path 支持 "a.wav|b.wav" 写法，多个参考音频会共同影响音色。

**同类**：CosyVoice2（阿里，零样本）、F5-TTS、IndexTTS（B站开源）。

### 方案 B：音色转换（**混合两个 CV 的正确做法**）

**关键洞察**：直接用日配参考去克隆，说中文会带**日式口音**——因为发音习惯来自参考音频。

正确顺序是把**发音**和**音色**解耦：

    中文 TTS（百度/Google，保证中文发音正确）
        ↓ 音频
    RVC / so-vits-svc（把音色转换成目标音色）
        ↓
    中文发音正确 + 爱丽丝音色

"混合两个 CV" 在这里的落点是 RVC 的**模型融合**（model fusion / ckpt merge）：

    merged = w × model_日配 + (1 − w) × model_中配

w = 0.5 就是各占一半，调 w 即可在两者之间滑动。

项目已把这个环节实现为可插拔的包装层（VoiceConvertedTTS）：

    TTS_VC_URL=http://127.0.0.1:7890
    TTS_VC_MODEL=alice
    TTS_VC_BLEND=alice_ja:0.5,alice_zh:0.5
    TTS_VC_PITCH=0

**转换服务端的契约**（需你自行适配到 RVC）：

    POST {TTS_VC_URL}/convert
    Content-Type: multipart/form-data
      audio  = <音频文件>
      model  = alice
      blend  = alice_ja:0.5,alice_zh:0.5
    -> 返回音频字节

### 方案 C：微调（效果最好，成本最高）

GPT-SoVITS 微调：约 1 分钟以上干净音频；RVC 训练：10 分钟以上。
本机 RTX 4060 8GB 可以跑推理，微调需要更长时间但可行。

## 五、更稳妥的选项（我的建议）

按风险从低到高：

1. **原创音色**（最干净）：用你自己的声音，或请配音爱好者录一段并**签声音使用许可**，再训练音色。完全避开他人声音权。
2. **取得授权的音色**：主动联系中配演员或其经纪方，签许可合同（民法典第 1021、1022 条明确声音可以许可他人商业使用并获酬）。这是**唯一能让"像爱丽丝"合法上路**的路径。
3. **挑一个音色接近的通用音色**：不克隆任何人，只求"语气像"。零法律风险，现在的 baidu / google 免费 TTS 就能用，只是音色是通用女声。
4. **纯自己玩、不公开**：风险最低但也不是零；至少不要公开传播生成的音频。

**我不建议**：把克隆音色用在公开运营的机器人上而不取得授权。这正好落在那个 2025 年入库判例的射程里。

### 一个现实可行的路径：直接找本人授权

查证时发现，皛四白是有公开活动、会以「特邀爱丽丝CV」身份出席线下活动（如南宁 BAO5.0）
的配音演员，属于**可以接触到的个人**。相比事后诉讼，主动取得授权成本更低：

1. **联系本人**：通过其 B 站账号或公开商务渠道，说明用途（角色陪伴机器人）、
   使用范围（公开群/私聊）、是否商用，谈许可——民法典第 1021、1022 条明确
   声音可以许可他人商业使用并获酬。
2. **注意可能还涉及游戏发行方**：国服中配是发行方委托录制的，那段录音的
   **表演者权与录制者权**可能同时牵涉演员与发行方。只拿到演员许可，
   不一定覆盖对「游戏语音素材」的使用。
3. **留下书面记录**：授权范围、期限、地域、是否可转授权、能否用于 AI 训练——
   尤其「**能否用于 AI 音色训练**」必须写清楚，这是这类合作特有的条款。

**没有授权时更干净的替代**：请一位愿意授权的配音爱好者（包括你自己）录参考音频，
训练出**原创音色**。听起来不像爱丽丝本人，但完全合规，也没有下架风险。

## 六、当前项目已落地的部分

无论你最终选哪条路，**接入点都已经做好了**：

- TTS_PROVIDER = baidu | google | openai_compatible | gptsovits（免费的两个开箱可用）
- TTS_CLONE_REF_AUDIO + TTS_CLONE_REF_AUDIO_2 → 多参考音频（音色混合）
- TTS_VC_URL + TTS_VC_BLEND → 音色转换层（方案 B，发音与音色解耦）
- 音色转换失败时**退回未转换音频并标明**"未转换"，不会假装音色已生效
- 提示词中明确禁止声称"官方配音"或"复制了官方演员声音"

也就是说：**你解决授权问题后，配置几行就能接上**；在那之前，免费 TTS 已经能用。

## 八、混合权重：更偏日配

按方案设定为**日配权重更高**：

    TTS_VC_BLEND=alice_ja:0.7,alice_zh:0.3

含义是音色由日配模型占 7 成、中配占 3 成。

**为什么这样不会带日式口音**：发音与音色是解耦的——

    中文 TTS（百度/Google）→ 发音已经是标准中文
        ↓
    VC 混合（日配 0.7 + 中配 0.3）→ 只改音色，不改发音

所以"偏日配"只影响听起来的音色，不会把中文念成日式腔调。
这正是方案 B 相比"直接用日配参考做零样本克隆"的关键优势。

**调参建议**：

| 权重 | 效果 |
| --- | --- |
| alice_ja:1.0 | 纯日配音色（最像原版，但通常也是法律风险最高的用法） |
| **alice_ja:0.7,alice_zh:0.3** | **本次采用**：明显偏日配，同时保留一点中配的中文语感 |
| alice_ja:0.5,alice_zh:0.5 | 均衡 |
| alice_ja:0.3,alice_zh:0.7 | 偏中配 |

RVC 侧的落点：模型融合（ckpt merge）时按上述比例对两个模型的权重做加权平均。
具体做法取决于你用的 RVC 版本，WebUI 里一般叫「模型融合 / Model Fusion」。

## 九、参考音频准备清单

1. **来源**：游戏内中文语音（角色语音/主线），或向本人索要的干净录音。
2. **格式**：wav，单声道，16k~32kHz。
3. **必须去掉背景音乐与音效**——BGM 会被一起学进去，生成出来会带杂音。
4. **时长**：零样本 5~10 秒；微调需要 1 分钟以上（建议切成 5~10 秒的片段）。
5. **只含目标角色一人说话**：无他人插话、无回声、无爆音。
6. **配套文本**：参考音频里**逐字**说的话（prompt_text），错一个字音色就会飘。
7. **语言参数**：中文参考配 text_lang=zh —— 这是「中文用中文CV」在参数上的落地。

这一步**无法自动化**，必须人工听一遍：确认没有人声重叠、没有音乐、没有爆音。

## 十、情感色彩

情感与音色是两条独立的线：

    文本 -> 情感推断（确定性规则）
              |
    中文 TTS（发音）---> 情感参考音频/instructions（语气）
              |
    音色转换（只改音色，保留语调起伏）

**关键点**：情感必须传给**合成**阶段，不能传给音色转换阶段——
语气在合成时就定下来了，RVC 这类转换只替换音色、会保留原有的语调起伏。

**用情感参考音频实现**：同一个克隆音色，换一段带情绪的参考音频，
生成出来的语气就会跟着变。GPT-SoVITS 支持 emo_ref_audio_path + emo_alpha：

    TTS_EMOTION_REFS=happy=/voices/happy.wav,sad=/voices/sad.wav,excited=/voices/excited.wav
    TTS_EMOTION_ALPHA=0.7

所以准备参考音频时，**每种情绪录一段**，是让克隆音色"有感情"的最实际办法。

**免费端点做不到**：百度/Google 的公开 TTS 接口没有情感参数。
它们在项目里被标注为 supports_emotion = False，返回值会带上
emotion_applied = False 和说明——不会让你误以为语音带了情绪。
