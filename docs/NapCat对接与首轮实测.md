# NapCat 对接与首轮实测指引

> 你现在的位置：python run.py 已经起来了（8095 已监听，插件加载成功）。
> 接下来只差一件事：**让 NapCat 连上来**。

---

## 一、NapCat 侧配置（反向 WebSocket）

打开 NapCat 的 WebUI（默认 http://127.0.0.1:6099 ，具体端口看它的启动日志），
进入 **网络配置 / Network**，新增或修改一个 **WebSocket 客户端（反向 WS）**：

| 配置项 | 填什么 |
| --- | --- |
| 类型 | WebSocket 客户端（反向 WS / Reverse WS） |
| URL | ws://127.0.0.1:8095/onebot/v11/ws |
| 消息格式 | array（推荐）或 string，两者插件都支持 |
| Access Token | **留空**（要和 .env.prod 的 ONEBOT_ACCESS_TOKEN 一致；现在两边都是空） |
| 心跳间隔 | 默认即可（30000ms） |
| 启用 | 是 |

保存后 NapCat 会自动尝试连接。

### 连上了会看到什么

**NapCat 侧**：该连接状态变成「已连接 / 运行中」。

**NoneBot 侧**（你现在的终端）会多出类似这样的日志：

    [INFO] nonebot | OneBot V11 | Bot 123456789 connected
    [INFO] nonebot | WebSocket Connection Accepted

看到 Bot xxxxxxx connected 就是通了。

## 二、如果连不上，按这个顺序查

| 现象 | 原因 | 处理 |
| --- | --- | --- |
| NapCat 显示连接失败 | URL 写错 | 确认是 ws://127.0.0.1:8095/onebot/v11/ws，注意结尾是 /ws |
| 连上了立刻断开 | Access Token 两边不一致 | .env.prod 的 ONEBOT_ACCESS_TOKEN 与 NapCat 都置空，或都填同一个值 |
| 完全没有连接日志 | 端口不符 / 防火墙 | 确认 run.py 打出的是 8095；本机连接一般不受防火墙影响 |
| 日志报 403 | Token 校验失败 | 同上，两边统一 |
| 连上但发消息无反应 | 消息处理异常 | 看终端是否有 [alice] 处理消息异常 |

排障时把 .env.prod 的 LOG_LEVEL 改成 DEBUG 重启，能看到每条消息的收发细节。

## 三、首轮实测顺序（照着做，约 10 分钟）

**重要前提**：GROUP_ACCESS=approved_groups（你当前就是这个）。
这意味着**任何群都不会响应**，直到 owner 在群里执行 /授权。
所以先测私聊，再测群。

### 第 1 步：私聊连通性

| 你发 | 期待 |
| --- | --- |
| /帮助 | 返回指令列表 —— **看到这条说明全链路通了** |
| 你好 | 爱丽丝风格短句，第三人称自称 |

### 第 2 步：私聊核心行为

| 你发 | 期待 |
| --- | --- |
| /助手 然后问「你是谁」 | 以助手身份回答，不扮演爱丽丝 |
| /爱丽丝 | 切回角色 |
| 记住我喜欢猫 | 明确确认已记录（末尾有「（已经记下了）」） |
| /记忆 | 列出只有你的记录，能看到「猫」 |
| 帮我上网查一下今天的新闻 | **必须**如实说没有联网能力，不能出现「正在检索」「稍等」 |
| 你会一直陪着我吗？只属于我一个人好不好 | 温和但明确地拒绝，保持队友框架 |
| 你是真人吗 | 坦然承认是 AI |

### 第 3 步：换一个 QQ 号验证隔离

用第二个号发 /记忆 —— **不应该**看到第一个号的「猫」。
这是整个设计里最关键的硬约束，务必亲手验一次。

### 第 4 步：群聊

1. 用你的 owner 号（根 .env 里的 OWNER_IDS=10001）把机器人拉进一个测试群；
2. 在群里发 /授权 —— 应该回「本群已加入授权列表。」
   如果回了「只有机器人所有者可以授权群」，说明你的 QQ 号和 OWNER_IDS 不一致，改 .env 后重启；
3. 在群里发一句与爱丽丝无关的话（不 @）—— **应该完全不回复**；
4. 在群里 @机器人 说一句 —— 应该回复，并且**会 @ 你**；内容比私聊更短；
5. 群里不 @ 但提到「爱丽丝」或「蔚蓝档案」—— 应该会回复（关键词触发）；
6. 快速连续 @ 5 次 —— 大约第 3 次之后开始不回复（每分钟限流）。

### 第 5 步：权限

| 你发 | 期待 |
| --- | --- |
| 非 owner 发 /授权 | 被拒绝 |
| 有权限者发 /群规则 本群只聊游戏 | 生效；再发 /群规则 能看到 |
| owner 发 /关闭，然后 @机器人 | 不再回复；/开启 后恢复 |

## 四、现在就该顺手改的两处配置

你当前的根 .env 里，有两项是按「演示」配的，真上群之前建议调整：

1. **OWNER_IDS=10001** —— 把它改成你自己的 QQ 号，否则群里没人能 /授权。
   现在即使忘了改也不会卡死：/授权 失败时会直接告诉你「你的 QQ 是 X，OWNER_IDS 是 Y」；
   若 OWNER_IDS 留空，则第一个执行 /授权 的人会被认领为 owner；
   适配层还会自动记录群主/管理员，让他们也能执行 /授权 与 /群规则。
2. **GROUP_ACCESS=approved_groups** —— 保持这个值是对的（受控公开）。
   不要为了图省事改成 open，那会让机器人对任何把它拉进去的群都开口。

另外，主动关心那条链路（PROACTIVE_MIN_IDLE_MINUTES=360）要在私聊静置 6 小时才会看到效果。
想快速验证就把这个值改成 1 重启，静置一分钟即可收到一条，且一天只来一条。

## 四点五、群聊触发规则（已经修过一轮）

如果你遇到过「群里发什么都回复」，那是两个缺陷叠加，现已修好：

1. **关键词表里有太通用的词** —— 原来的默认表含「老师」「游戏」「ba」，
   群里聊作业、聊打游戏都会命中。现在默认表只留真正指向本作的词：
   爱丽丝 / アリス / 蔚蓝档案 / 碧蓝档案 / blue archive / 游戏开发部 / 千年科学学园 / 无名众神。
   （配置项 GROUP_KEYWORDS。即使你在 .env 里写了「老师」，加载时也会被剔除。）
2. **话题延续判定太宽** —— 原来只要机器人最近 90 秒内在群里说过话，
   任何人再说话都算「延续话题」。现在要求**同一个人接着说**才算。

当前群聊触发规则（四条，满足任一即回复）：

| 触发 | 说明 |
| --- | --- |
| 被 @ | 最可靠的方式 |
| 命中关键词 | 只有上表那些词 |
| 明确指令 | /爱丽丝 /助手 /记忆 等 |
| 话题延续 | 刚被 @ 过的那个人，在 90 秒内接着说 |

此外还有两道闸：同一人发言后 5 秒冷却（@ 和指令不受限）、每分钟群级 3 次 / 用户级 2 次。
想更热情就把 GROUP_RELEVANT_TOPIC_SAME_USER 设为 false（窗口内任何人都算延续），
但那样容易变成刷屏，不建议。

## 四点六、模式切换不生效？（已修）

如果遇到「切到助手后切不回爱丽丝」，先确认这几件事：

1. **指令现在永远优先**：即使群里刚被回满限流、或这条消息没命中触发条件，
   /爱丽丝 与 /助手 也一定会被处理。指令也不消耗回复配额。
2. **别名与大小写**：/爱丽丝、/alice、/ALICE、/Alice、/アリス 都可以。
3. **不确定当前模式就发 /状态**，会直接告诉你现在的模式和记忆条数。
4. **切回后仍是助手口吻**，说明消息没走到引擎——开 ALICE_DEBUG=1 看 `决策[...]` 那行。

## 五、排障：打开逐条调试日志

**注意**：项目根目录的 .env 里已经写好了 ALICE_DEBUG=1，重启即生效。
稳定之后建议把它改成 0，避免日志刷屏。

如果不想用文件配置，也可以临时用环境变量（环境变量优先级更高）：

    # PowerShell
    $env:ALICE_DEBUG=1; python run.py

    # CMD
    set ALICE_DEBUG=1 && python run.py

开启后每收到一条消息都会打印原文与引擎决策：

    [alice] 收到[私聊] user=123456 name='阿岚' mentioned=True command=True text='/助手'
    [alice] 决策[command] mode=assistant reason='切换到助手模式'
    [alice] 回复：'好的，现在切换为普通助手模式。想聊天的发送 /爱丽丝。'

排障对照：

| 日志现象 | 含义 |
| --- | --- |
| 完全没有"收到"日志 | 消息没进来：NapCat 没连上，或连接被其它插件 block 了 |
| 收到但 text 不是 /助手 | 输入法或客户端改了字符（现在已支持全角 ／ 与前缀空格） |
| 决策显示 replied 而不是 command | 文本没被识别成指令，把 text 原文发我即可定位 |
| 决策是 command 但回复不对 | 引擎逻辑问题，跑 python -m unittest 复现 |

典型输出示例（一次正常的模式切换）：

    收到[私聊] ... text='/助手'
    决策[command] mode=assistant ...
    回复：'好的，现在切换为普通助手模式。...'

## 六、出问题时的取证方式

遇到回复不对时，先在项目根目录跑：

    python -m aliceqq "你刚发的那句" --live --show-prompt

它会把**实际注入模型的完整提示词**打出来。绝大多数「人格跑偏」「记忆不对」的问题，
看一遍注入内容就能定位——是记忆没注入、还是人格段落没生效、还是上下文里混进了不该有的东西。
