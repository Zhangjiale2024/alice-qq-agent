## 二、"先"字被切掉：根因与修法

### 根因（这次查实了，之前只是怀疑）

参考片段 `same4_f414_flat06.wav` = `refs\ja_full.wav` 的 **304.000 ~ 312.000 秒**，
这一点用归一化互相关验证过，相关系数 **1.0000**（逐样点平均差 0.0116，
差异来自当时的增益归一化）。

用 faster-whisper 的词级时间戳看，那句台词的第一个词"先生"的真实起止是：

    ja_full.wav  313.10s 附近那句:  先生と初めて会ったまさにその日です
    而 304 秒附近那句:              先生の人生初の接続日ですね…

    "先生" 的词起点 = 303.69s
    当初切片起点   = 304.00s     <- 晚了 0.31 秒

303.69~304.00 这 0.31 秒正是"先"字的**起音**（包含辅音和元音起始的过渡）。
切掉之后 whisper 转写就把首字读成了别的音：

    same4 转写      : 女性の人生初の接続日ですね…        <- "先生の" 被听成 "女性の"
    完整句转写      : 先生の人生初の接続日ですね…        <- 修好后

所以交接文档第八节里那条"生の人生初の…"，以及"切片把开头的先字切掉了"的
判断**方向完全正确**。唯一要更正的是它给的完整转写：
文档写"先生、人生初の接続日ですね。今この瞬間が…"，
而实测该片段是"**先生の**人生初の接続日ですね、今この瞬間が…"
（是"先生の"不是"先生、"）。这条已在本报告更正。

### 为什么会切错

当初（`48_same_source_clean.py`）用 **整数秒滑窗**扫片段：

```python
for start in range(0, int(len(y)/sr) - 8, 1):   # 起点只能是 0,1,2,... 整数秒
```

整数秒网格和词的边界**没有任何关系**，撞上字中间的概率约等于随机。

### 修法（不是加 0.1 秒，是改成对齐语音边界 + 强制保护余量）

1. 用能量包络找有声区间（阈值取 max(噪声底×3, 峰值×2%)）
2. 片段起点 = 有声起点 − 0.25 秒，终点 = 有声终点 + 0.25 秒
3. 再在首尾**显式补 0.15~0.20 秒数字静音**

第 3 步是关键。第一版仅靠能量阈值对齐时，8 个候选的"起始余量"全是 0.000 秒——
因为这段音频有背景音乐，句首音乐渐入被当成静音，于是又切到了字。
补上真正的数字静音才彻底解决。

### 验证

| 片段 | 起始余量 | 结尾余量 | 转写首词 |
|---|---|---|---|
| same4（旧） | **0.000s** | **0.000s** | 女性の… （首字被切） |
| padb_304_400（新） | 0.320s | 0.190s | **先生の人生初の…** |

8 个候选全部通过"起始/结尾余量 >= 0.10 秒"检查，见
`models_shared\refs_padded\check.json`。

## 三、音源与扩数据

### 搜索链路自己修好了

第一轮搜索（`72_find_sources.py`）5 个关键词里 3 个直接 412。原因：
**B站 2023 年起搜索接口要 WBI 签名**（`w_rid`），不带签名就 412。

已经写好可复用的 `bili_api.py`：

- WBI 签名（img_key/sub_key → mixin_key → md5）
- **关键坑**：未登录时 `x/web-interface/nav` 返回 `code=-101`（账号未登录），
  但 `data.wbi_img` **照样有值**。按 `code==0` 判断就永远拿不到 key。
  改成只看 `data.wbi_img` 是否存在。

顺带查出：`.env` 里的 `BILIBILI_SESSDATA` 是**假的占位值**
（`e3ec0360%2C...`，34 字符，真实 SESSDATA 有 60~80 字符），
所以之前下载到的音频全是**未登录的最低码率档**。机器人检索功能可能也受影响。

### 爱丽丝素材码率全景（实测）

| BV | 码率 | 时长 | 说明 |
|---|---|---|---|
| BV14v4y1e7QC | 68k | 7:16 | 当前认可源（Usensei，CV 田中美海） |
| BV1ZM411n74G | 99k | 8:07 | 已下过 |
| BV1vj6yBDERt | 82k | 13:44 | **新增**，内容最长 |
| BV1Qg4y177bK | 86k | 11:10 | **新增**，爱丽丝（女仆） |

| BV1Mre8ziE2V | 184k | 3:18 | **新增**，战争雷霆游戏内录（混了音效） |

**重点结论：找不到明显更好的纯语音源。** 那两个 169/184 kbps 的是游戏内录，
音效和音乐混在一起，当参考音频不如现在的 68k 源。B站普通用户投稿的
音频档上限就是 30280（约 132k AAC），所谓"高码率"基本都来自游戏内录或 ASMR。

### 4.3 最终判据：用 ASR 反查合成产物能不能听懂

这是本次最硬的一条验证，建议以后作为参考音频的**准入测试**：

做法是把每个候选参考的合成产物**再转写一遍**，看能不能还原中文原文。
覆盖率高 = 发音清楚；覆盖率低 = 合成出来的根本不是中文。

轮1（19 字短句）结果：

    参考                        产物听感覆盖   转写回显
    00 当前在用 same4             12/16 字    你好我是埃利斯今天也要一起加油
    01 同句修好首字 padb304        12/16 字    你好我是愛麗絲今天也要一起加油   <- 且"爱丽丝"更准
    ja_049_f409                 12/16 字    你好我是艾尼斯今天也要一起加油
    ja4_643_f466                12/16 字    你好我是愛你死今天也要一起加油   <- 已被污染
    ja4_008_f409_flat01          5/16 字    你好我帅死今天愛死者了
    ja3_753_f368                 4/16 字    喉!我殺你死!今天我已死定了!
    ja4_003_f411_flat00          2/16 字    以後,我們要死!我們要死!
    ja5_wotb_006_f354            4/16 字    不!我肯定是!今天我就是這樣!
    ja6_wotb_122_f351            2/16 字    喵我嘻哈你死心情用意死者喵

轮2（48 字长句）：

    00 当前在用 same4             36/40 字    完整、连贯通顺
    01 同句修好首字 padb304        38/40 字    最好，且"散步/爱丽丝"都对
    ja_049_f409                 38/40 字    好
    ja4_643_f466                34/40 字    尾部已经跑偏成"游走器也"

**结论：只有"同源"参考（ja_full 里的片段）能稳定合成出可懂的中文。**
换源（ja3/ja4/ja5/ja6）虽然指标更漂亮，但合成出来的是乱码——
这正是坑5 警告的"指标改善但听感更差"，而且这次差到**根本听不懂**。

也就是说，A 计划里"换更好音源"这条路，**目前找不到可用的替代源**。
真正有收益的是**同源换片段 + 修掉首字**，即 `padb_304_400.wav`。

### 4.4 一个必须警惕的发现

按"平坦度越低越干净"筛，会选出**平坦度 0.0022 的片段**——
而语音的平坦度通常在 0.02~0.1。那些片段其实是**静音或纯音乐**：
静音没有谱结构，平坦度自然趋近 0。

这是坑5（"指标只能证伪"）的又一个实例，而且更隐蔽：
**筛选指标自己会指向完全错误的答案**。修正办法是加"有声占比 >= 0.75"
和"用 ASR 确认真的有话"两道闸门。加之前 8 个候选全是静音/音乐，
加之后只剩 7 个合格。
